# Step 2: training data from the model's own verified answers

Output of `notebooks/Step2_Training_Data.ipynb` on Kaggle (2x T4, float16), 2026-11-10.

Every example is *question → direct, correct answer*, written by LFM3-1.7B itself:

- **Pass A:** every question answered with thinking **OFF**.
- **Pass B:** questions that pass A got wrong are answered again with thinking **ON**, 2 tries each.
- **Checked automatically:**
  - code must pass its tests;
  - math must match the reference number;
  - instructions must pass Google's IFEval checker;
  - tool calls must match the reference calls.
- **Kept:** for each question, the shortest correct final answer, with any thinking removed.

No other company's model was used. All questions come from openly licensed **training** splits, and a 13-word-overlap check removed anything similar to our benchmarks.

## Result

**2,069 examples:** 1,966 for training and 103 for validation, from 2,575 questions.

## Quality checks

- **0** answers contain `<think>` or `</think>`.
- **23** answers contain "wait / hmm / let me think"-style phrases (17 math, 4 code, 2 instructions). They are still correct and short.
- **Tool calls include several calls at once:**
  - 221 of 424 tool answers make 2 or more calls (97 make 2, 96 make 3, 28 make 4 or more);
  - that is the weak spot found in the baseline, where thinking OFF lost 13 points on BFCL, mostly on parallel calls.
- Every tool example and every "no tool needed" example stores its tool definitions in `tools`, so training shows the same prompt the model sees in real use.

## Known weak spots

1. **Not much code: 268 examples (13%).**
   - Code is where thinking OFF loses most (MBPP+ −11 points) or secretly keeps thinking (HumanEval+ 70% of the time).
   - APPS mostly failed: with thinking ON, 97% of attempts hit the 4,096-token limit.
   - If code stays behind after fine-tuning, the next data round should add more short code problems with tests.
2. **61 of the code answers include an "Approach / Explanation" write-up** next to the code. They are correct, just longer than needed.
3. **Tool-call matching is strict.** Some answers that look right were rejected because of small formatting differences from the reference. That only costs examples, never quality.
